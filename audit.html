The headline: no two devices can ever connect, and nothing is wired up anyway

Every module in shunkan-core is individually plausible and individually tested. But the QUIC transport's public API cannot establish a single connection — each side generates its own throwaway certificate and trusts only itself, so every handshake dies with BadSignature. I reproduced this directly.

It stays green in CI because the one test that exercises client-to-server (transport.rs:290) throws away the public API and hand-builds a shared config — it tests a code path that ships to nobody.

Even with that fixed, nothing would happen: the desktop daemon never calls the core library. Its mDNS and QUIC functions are loop { sleep } stubs that log heartbeats. Every Tauri command returns an empty vector. The frontend talks to a Tauri runtime that isn't a dependency of the project.

The gap to close is not code volume — it's that the pieces have never been connected to each other. Treat every "complete" and "implement" in the commit log as "scaffolded".

Blocking defects

Each of these alone prevents the product from functioning at all. Nothing downstream is testable until they're closed.

F-01Critical

Every peer trusts only its own certificate, so the QUIC handshake can never succeed

core/src/crypto.rs:61–110 · core/src/transport.rs:49, 104

generate_self_signed_cert() mints a fresh keypair on every call and builds a client config whose root store contains that same cert. TransportServer::start() and TransportClient::new() each call it independently, so the client trusts a certificate the server has never seen.

reproduced TransportClient::new() → connect(TransportServer addr)
Err("Failed to establish QUIC connection: the cryptographic
     handshake failed: error 51: invalid peer certificate:
     BadSignature")

FixGenerate one long-lived device identity keypair, persist it (~/.local/share/shunkan/), and derive the cert from it. Peer trust comes from a paired-device store of cert fingerprints, verified by a custom rustls::client::danger::ServerCertVerifier that accepts a peer only if its fingerprint was pinned at pairing time. Delete the shared-config workaround in the test and make the test drive the real public API.

F-02Critical

The desktop daemon never calls shunkan-core; discovery and transport are sleep loops

desktop-linux/src-tauri/src/main.rs:98–150 · commands.rs:110–160

run_mdns_discovery and run_quic_listener log "would advertise…" / "would listen…" and then sleep forever. Neither imports discovery or transport. All five IPC commands return vec![] / false. The clipboard callback logs a hash and drops the item on the floor.

FixBuild a single AppState holding DiscoveryService, a peer-connection map, and ClipboardHistory behind an Arc. Wire the three tasks to it, make the clipboard callback push into history and fan out to connected peers, and back each command with real state.

F-03Critical

The mDNS service advertises zero IP addresses, so peers can resolve it but never reach it

core/src/discovery.rs:83–90

The address argument is "" with the comment "Let the daemon pick the IP". It does not: mdns-sd's AsIpAddrs for &str returns an empty set for an empty string, and ServiceInfo::new defaults addr_auto: false. The service record is published with no A/AAAA records.

FixChain .enable_addr_auto() onto the ServiceInfo, which is exactly the API for "let the daemon track host addresses". Add an integration test asserting a resolved peer has a non-empty addresses vector.

F-04Critical

TXT properties are built and then silently thrown away

core/src/discovery.rs:77–90

register() loops over its properties argument building a txt_properties vector, then passes None to ServiceInfo::new and never uses it. Peer ID, platform, and protocol version are never advertised — so discovered peers can't be identified, version-checked, or matched to a pairing record.

FixPass the properties through as a HashMap<String, String>. Define the TXT schema explicitly (id, platform, ver, fp for cert fingerprint) since F-01's trust model will need the fingerprint here.

Correctness bugs

Logic that is wired up but behaves incorrectly — panics, data loss, and silent state corruption.

F-05Major

Clipboard preview panics on any non-ASCII text longer than 200 bytes

desktop-linux/src-tauri/src/commands.rs:62, 72

&text[..200] slices by byte offset. Copy a paragraph of Japanese, Cyrillic, or an emoji-laden message and byte 200 lands mid-codepoint, panicking the command handler. The existing test only uses "a".repeat(500), so it never catches this.

reproduced "日".repeat(300)[..200] → panic:
byte index 200 is not a char boundary

FixTruncate on character boundaries: text.char_indices().nth(200).map_or(text.len(), |(i, _)| i). Apply to both the PlainText and RichText arms, and add a multibyte case to the test.

F-06Major

Clipboard writes vanish immediately on X11

desktop-linux/src-tauri/src/clipboard.rs:194–218, 145–147

write_to_clipboard constructs a local Clipboard, sets the text, and returns — dropping it. On X11 the clipboard is a live ownership protocol, not a store: when the owning connection goes away, the content goes with it. Pasted text will be empty or stale. The same constructor also runs on every 500 ms poll, opening a new X11/Wayland connection twenty times a minute.

FixHold one Clipboard for the process lifetime inside the monitor. On X11 use arboard's SetExtLinux::wait() on a dedicated owner thread so the selection survives. This is the concrete form of the tiered strategy ADR-004 already describes but no code implements.

F-07Major

The feedback-loop guard never resets, permanently blocking one clipboard value

desktop-linux/src-tauri/src/clipboard.rs:103, 200–204, 167–174

last_written_hash is set when we write remote content and is never cleared. Any future deliberate copy of that same text by the user is silently discarded forever. Receive a password from your phone once and you can never re-share it from that desktop again.

FixMake the guard one-shot — clear it the first time it suppresses a poll — or scope it to a short window (hash plus an Instant, expiring after ~2 s). One-shot is the more predictable of the two.

F-08Major

Every message opens its own QUIC stream, so ordering is not guaranteed

core/src/transport.rs:147–189

send_message calls open_uni() per message and recv_message calls accept_uni() per message. QUIC streams are independent and explicitly unordered relative to each other — that's the head-of-line-blocking property the architecture doc praises. Applied per message, it means a stale clipboard item can land after and overwrite a newer one, and file chunks arrive shuffled. There is no reassembly or reordering code anywhere.

FixUse streams as logical channels, not as envelopes: one long-lived ordered stream for clipboard and control traffic, one stream per file transfer. Add a monotonic sequence number to clipboard messages and drop out-of-order arrivals. Write the reassembly path — chunk_index and total_chunks exist in the protocol but nothing consumes them.

F-09Minor

Re-copying existing content keeps the original timestamp

core/src/history.rs:44–54

The dedup branch moves the entry to the front but returns before touching timestamp or source_peer. The UI orders by position but displays the stale time, so something copied one second ago reads "3h ago".

FixUpdate the stored entry's timestamp and source from the incoming item before re-inserting it at the front.

F-10Minor

keep_alive_ms is dead configuration; idle connections will silently drop

core/src/transport.rs:26, 33

The field is set, defaulted, and asserted in three tests, but never applied to a quinn::TransportConfig. With no keep-alive, a paired connection dies at quinn's default idle timeout, and nothing reconnects.

FixBuild a quinn::TransportConfig, call keep_alive_interval() and max_idle_timeout(), and attach it to both endpoint configs. Add reconnect-on-idle-close handling.

F-11Minor

Clipboard read errors are swallowed into a success value

desktop-linux/src-tauri/src/clipboard.rs:149–159

Every get_text error returns Ok(None), which is indistinguishable from "clipboard unchanged". A permanently broken display connection looks identical to an idle clipboard, and the Err arm of the monitor loop is effectively unreachable.

FixKeep ContentNotAvailable as Ok(None); propagate real errors. Have the loop count consecutive failures and back off or re-initialize rather than spinning silently.

F-12Minor

Blocking display-server I/O runs directly on the async runtime

desktop-linux/src-tauri/src/clipboard.rs:230–254

run_monitor_loop is async, but poll_for_changes performs synchronous X11/Wayland round-trips inside it. A slow or hung compositor stalls the whole tokio worker, including QUIC.

FixWrap the poll in tokio::task::spawn_blocking, or move clipboard ownership to a dedicated OS thread that communicates over an mpsc channel — which the event-driven rewrite in F-24 needs anyway.

F-13Minor

Self-filtering in discovery is substring-based and order-dependent

core/src/discovery.rs:119, 127–132

Two problems. The filter is instance.contains(our), so a peer named thinkpad would suppress helliot-thinkpad. And our_instance is captured when browse() is called — call browse() before register() and the filter is None forever, so the device discovers itself.

FixCompare full service names for equality, and share the instance name via Arc<Mutex<Option<String>>> so registration order doesn't matter. Better still, filter on the peer ID from the TXT record once F-04 lands.

Security

The product's stated promise is that OTP codes and passwords never leave the LAN. The current pairing and authorization story does not deliver that.

F-14Critical

PIN pairing is decorative — and nothing ever checks it

core/src/crypto.rs:35–47 · core/src/protocol.rs:65

The wire value is an unsalted BLAKE3("shunkan-pin-v1:" || pin) over a six-digit space. All 106 candidates can be enumerated in milliseconds, so anyone who sniffs one handshake recovers the PIN — and the value is static, so it replays. More fundamentally: no code anywhere reads Handshake.pin_hash. There is no verification path, failed-attempt limit, or pairing state machine. REQ-CORE-02 is unimplemented.

FixUse a real PAKE — spake2 over the six-digit secret — so the exchange yields a shared key without exposing the PIN, and bind the resulting key to the TLS certificate fingerprints of both sides. If a PAKE is out of scope for now, the minimum viable version is a salted, session-nonce-bound commitment plus rate limiting. Compare with subtle::ConstantTimeEq, not == (crypto.rs:45).

F-15Major

The X25519 keypair is 32 random bytes labelled "public key"

core/src/crypto.rs:112–135

KeyPair::generate_placeholder fills a vector from the RNG. There is no private key, no curve operation, and no Diffie-Hellman. It is doc-commented as a scaffold, but it is a pub type named KeyPair with a public_key field, which is exactly the shape a caller would trust. x25519-dalek isn't even a dependency.

FixEither implement it properly with x25519-dalek (EphemeralSecret / PublicKey, returning a real shared secret), or delete the type entirely until it's needed. A convincing-looking fake in a crypto module is worse than an absence.

F-16Major

Any device on the LAN can connect; there is no authorization layer

core/src/transport.rs:67–80 · core/src/crypto.rs:78

accept() returns every incoming connection with no handshake validation, no pairing check, and no allowlist; the server is built with_no_client_auth(). Once F-01 is fixed in the obvious way, this becomes a clipboard that any machine on a café Wi-Fi can read from and inject into.

FixRequire the first frame on a new connection to be a Handshake that resolves to a known paired peer, with a short timeout, and close the connection otherwise. Enable mutual TLS against the paired-device cert store so unauthorized peers are rejected during the handshake rather than after it.

F-17Major

Unauthenticated peers control a 16 MiB allocation per stream

core/src/transport.rs:177–185, 236–243

The length prefix is read from the wire and used directly as vec![0u8; len]. The 16 MiB ceiling is per stream and streams are unbounded, so a peer that opens streams in a loop drives memory to exhaustion — against a daemon whose stated hard ceiling is 20 MB total (INV-01).

FixAuthenticate before allocating (F-16), set per-message-type limits far below 16 MiB, cap concurrent streams via quinn::TransportConfig::max_concurrent_uni_streams, and read into a bounded reusable buffer instead of allocating from an attacker-supplied number.

F-18Major

HTML attribute injection in the palette UI

desktop-linux/src/app.js:122–136, 156–161

escapeHtml is applied to text nodes but not to interpolated attributes: data-hash="${item.hash}", data-peer-id="${peer.id}", and title="${peer.platform}". Peer names and platform strings arrive over the network from an unauthenticated source (F-16), so a peer advertising linux" onmouseover="… executes script in the palette.

FixStop building markup from strings. Construct rows with document.createElement, textContent, and setAttribute — that closes the whole class rather than one instance of it.

F-19Minor

Device identity is regenerated every launch, so "silent reconnect" is impossible

desktop-linux/src-tauri/src/main.rs:37 · core/src/crypto.rs:61

PeerId::random() runs at startup and certificates are minted per call. Restart the daemon and every paired device sees a stranger. REQ-CORE-02's "stores mutual TLS certificates for silent future reconnects" has no storage layer at all.

FixPersist identity — peer ID, keypair, certificate, and the paired-peer store — under the XDG data directory with 0600 permissions, loaded once at startup.

Performance & invariant violations

Measured against the project's own stated targets: sub-50 ms text propagation, gigabit file transfer, and a 20 MB hard memory ceiling.

F-20Major

JSON encoding inflates binary payloads 3.57×

core/src/protocol.rs:216–237

serde_json renders Vec<u8> as a decimal array — [255,0,17,…] — so file chunks and images cost roughly 3.6 bytes of wire per byte of data, plus parse cost on both ends. That directly contradicts the "full Wi-Fi 6 bandwidth" goal and multiplies the memory footprint of every in-flight message.

measured 64 KiB FileChunk → framed message
raw       65,536 B
json     234,182 B     expansion 3.57×

FixSwitch the envelope to a binary codec — postcard or bincode, both already implied by the stack doc. Better still, keep JSON for small control messages and send file payloads as raw length-delimited bytes on their own stream, so chunk data never passes through a serializer.

F-21Major

Clipboard history is bounded by entry count but not by bytes

core/src/history.rs:14–21, 43–71

The cap is 100 entries of unbounded size, all resident, each holding a full Vec<u8>. A hundred copied screenshots is hundreds of megabytes against INV-01's 20 MB hard ceiling. The module doc cites INV-01 as the reason it avoids SQLite, which is the wrong lever — the payloads are the cost, not the index.

FixTrack total bytes and evict on whichever limit hits first. Set a per-entry maximum for inline storage and spill anything larger to a content-addressed file on disk, keeping only the hash and a path in memory.

F-22Minor

chunk_and_hash duplicates the entire file in memory

core/src/hashing.rs:70–82

chunk.to_vec() copies every chunk into a new allocation, so the returned vector is a second full copy of the input — which was already fully in memory to be passed as a slice. A 2 GB transfer, the exact scenario in the PRD's designer persona, needs 4 GB.

FixReturn borrowed slices (impl Iterator<Item = (&[u8], String)>), and add a streaming path that reads from a file handle chunk by chunk so a transfer's peak memory is one chunk, not one file.

F-23Minor

The "O(1) dedup" index is rebuilt from scratch on every insert

core/src/history.rs:66, 140–145

rebuild_index() clears the map and re-inserts every entry — cloning each hash string — on every push, every dedup hit, and every removal. The documented O(1) lookup sits behind an O(n) write with n string allocations.

FixIndex by a stable key rather than a positional one. Store entries in a slab or IndexMap and keep the deque holding keys, so ordering changes don't invalidate the index. At 100 entries this is not urgent — but the doc comment should not claim a property the code doesn't have.

F-24Minor

The latency budget is spent before a packet is sent

desktop-linux/src-tauri/src/clipboard.rs:124 · desktop-linux/src/app.js:310–313

A 500 ms clipboard poll plus a 2 s UI refresh means worst-case 2.5 s from copy to visible, against a stated sub-50 ms target. Polling is also the pattern INV-03 prohibits on Android, and this is the implementation that would be ported there.

FixGo event-driven, which the ADR already specifies: wl-clipboard-rs with ext-data-control-v1 on wlroots, XFixes selection notifications on X11. Push updates to the UI over Tauri events instead of having the frontend poll.

F-25Minor

compute_merkle_root is not a Merkle root

core/src/hashing.rs:89–99

It concatenates hex hashes into one hasher. That's a fine whole-file checksum, but it isn't a tree: you can't verify a chunk against a root without every other hash, and there are no partial-verification or repair paths. The name promises a structure the code doesn't build.

FixRename it compute_file_checksum, or build an actual binary tree if partial verification is wanted. Either way, add a domain separator and hash the raw 32-byte digests rather than their hex encoding.

Frontend & the missing Tauri layer

The desktop UI is a static page talking to a runtime the project does not depend on.

F-26Major

There is no Tauri app — and the IPC bridge targets the wrong API version

desktop-linux/src/app.js:31–37 · src-tauri/Cargo.toml

Three compounding problems. The crate is named src-tauri but has no tauri dependency, no tauri.conf.json, and no build.rs; main.rs is a plain tokio binary. None of the functions in commands.rs carry #[tauri::command] or are registered in a handler. And the bridge calls window.__TAURI__.invoke, which is the v1 shape — v2 exposes window.__TAURI__.core.invoke and only when withGlobalTauri is enabled. Argument names are snake_case where v2 expects camelCase. So window.__TAURI__ is always undefined and the UI silently runs on mockInvoke forever, which is why it looks like it works.

FixAdd the Tauri v2 dependency, config, and build script; annotate and register the commands; import invoke from @tauri-apps/api/core rather than reaching for a global. Keep the mock behind an explicit dev flag so a missing backend fails loudly instead of quietly rendering fake data.

F-27Minor

The 2-second refresh erases whatever the user is searching for

desktop-linux/src/app.js:287–305, 310–313

loadData assigns filteredHistory = [...history] without re-applying state.searchQuery, and setInterval runs it every two seconds. Type a query, wait two seconds, and the full list returns underneath you with the selection reset — while the search box still shows your text.

FixHave loadData call filterHistory() instead of overwriting the filtered list, and preserve the selected entry by hash rather than by index. Replacing polling with push events (F-24) removes the race altogether.

F-28Minor

Enter in the search box triggers a paste

desktop-linux/src/app.js:326, 210–237

The keydown handler is bound to document and doesn't check the event target, so ordinary typing in the search field competes with palette navigation. Pressing Enter to commit a search instead pastes the highlighted entry into the system clipboard.

FixScope arrow and Enter handling to palette context, and let the search input keep its own key events. Debounce the input handler while you're there — it currently re-renders the whole list per keystroke.

F-29Minor

Escape doesn't close, and a single click pastes without confirmation

desktop-linux/src/app.js:231–235, 260–268

Escape logs "would close overlay" to the console. Clicking anywhere on a history row immediately overwrites the system clipboard — no double-click, no confirm — so brushing a row while scanning silently replaces what you had copied.

FixWire Escape to getCurrentWindow().hide() once Tauri is real (F-26). Make single click select and Enter or double-click paste, matching the keyboard model the footer already advertises.

Build, CI, and the Android module

The pipeline that is supposed to catch the above cannot currently run to completion.

F-30Critical

CI fails on its first run — formatting and lints were never applied

.github/workflows/ci.yml:8–9, 36, 39

The workflow sets RUSTFLAGS: -D warnings globally and runs both cargo fmt --all --check and clippy -D warnings. I ran all three locally: formatting differs across multiple files, and there are roughly twenty warnings — unused imports (mpsc, Arc, Context, warn, PeerId), filter_map that should be map, from_str shadowing the FromStr trait, and dead code across all of commands.rs. Every job fails before the tests run.

FixRun cargo fmt --all and cargo clippy --fix, then resolve the rest by hand — most of the dead-code warnings disappear once F-02 wires the commands up. Add a pre-commit hook so this can't drift again.

F-31Minor

Cargo.lock is gitignored for a workspace that ships binaries

.gitignore:6

Applications should commit their lockfile. Without it, CI and every developer resolve dependencies independently, so a broken upstream release lands as an unreproducible failure and security review has no fixed dependency set to audit.

FixRemove the Cargo.lock line from .gitignore and commit the lockfile.

F-32Minor

The Android CI job builds nothing Android

.github/workflows/ci.yml:52–74

The job is titled "Build (Android Core & APK Skeleton)". It installs cargo-ndk and never invokes it, never touches Gradle, and runs only cargo check — which doesn't link, so it cannot surface the NDK linker and ABI problems that actually break Android builds.

FixEither build for real — cargo ndk -t arm64-v8a build plus ./gradlew assembleDebug — or rename the job to describe what it does. A green check that proves nothing is worse than no check.

F-33Critical

The Android module cannot be opened, let alone built

mobile-android/settings.gradle.kts:13 · app/build.gradle.kts:20

dependencyResolution { } is not valid Gradle DSL — the block is dependencyResolutionManagement — so evaluation fails before anything else is attempted. The module also has no Gradle wrapper, no AndroidManifest.xml, no Kotlin source of any kind, and no proguard-rules.pro despite build.gradle.kts referencing it. The whole module is three build files.

FixRename the settings block, add the wrapper, and scaffold the minimum real app — manifest, MainActivity, one Compose screen, the proguard file. Then reduce the claim in tasks.html to match what exists.

F-34Critical

INV-04 is unmet: there is no UniFFI, and no .so can be produced

core/Cargo.toml · mobile-android/app/build.gradle.kts:62–66

No uniffi dependency, no .udl file, no proc-macro exports, no build script, no uniffi-bindgen step. core/Cargo.toml also declares no crate-type, so it builds as an rlib only — libshunkan_core.so can never exist, and the Gradle comment pointing at jniLibs/ describes a file nothing generates. Commit be8ed60 says "uniffi ffi bindings setup"; there is none.

FixAdd crate-type = ["cdylib", "staticlib", "rlib"], take the uniffi dependency, and export the surface Android needs — discovery, pairing, send, receive-callback — via proc-macros. Add a cargo-ndk build step that emits the ABIs into jniLibs/ and a bindgen step that generates the Kotlin.

F-35Major

The Android clipboard-read path has no viable design

mobile-android/app/build.gradle.kts:13

minSdk = 29 is commented "Android 10+ required for clipboard restrictions", but Android 10 is precisely where background clipboard reads were removed: only the default IME or the focused app may read it. INV-03 rules out polling and prohibits AccessibilityService. So the desktop's poll-based model cannot be ported, and no alternative exists in code.

FixCommit to the event-driven surfaces the invariant already names: a ShunkanIME InputMethodService for capture, a ShareTarget for explicit sends, and a TileService for the quick toggle. Decide this before writing Kotlin — it determines the entire module's architecture, and it means Android→desktop clipboard sync is user-initiated by design, not automatic. That should be reflected in the PRD.

Suggested repair sequence

Ordered by dependency, not severity — each phase makes the next one testable. The phases are a real sequence; don't reorder them.

Phase 1

Make one link actually work

Persistent device identity and a real trust model, addresses and TXT records on the wire, the daemon wired to the core, and stream discipline so messages arrive in order.

F-01 · F-02 · F-03 · F-04 · F-08 · F-19

Exit  Two Linux machines on one LAN discover each other and sync a line of text, driven entirely through the public API.

Phase 2

Stop the bleeding

The panic, the vanishing X11 writes, the permanent clipboard block, the attribute injection, the unbounded allocation — plus getting CI green so it starts catching regressions instead of failing on formatting.

F-05 · F-06 · F-07 · F-11 · F-17 · F-18 · F-30 · F-31

Exit  A day of real use across CJK text, large images, and daemon restarts produces no panics and no lost clipboard writes.

Phase 3

Make pairing mean something

Replace the decorative PIN with a PAKE bound to certificate fingerprints, enforce authorization on every connection, and either implement or delete the X25519 placeholder. This is the phase that makes the privacy claim true.

F-14 · F-15 · F-16

Exit  An unpaired device on the same network cannot read, inject, or observe clipboard content — verified by a test that tries.

Phase 4

Meet the stated numbers

Binary wire format, byte-budgeted history, streaming chunk hashing, and event-driven clipboard capture. Add benchmarks and an idle-RSS check to CI so INV-01 and the latency target become enforced rather than aspirational.

F-20 · F-21 · F-22 · F-23 · F-24 · F-10 · F-25

Exit  Measured copy-to-paste latency and idle RSS are recorded in CI against the PRD's targets.

Phase 5

Build the actual desktop app

Adopt Tauri v2 properly — dependency, config, registered commands, real IPC — then fix the palette's search, selection, and keyboard behaviour on top of a backend that responds.

F-26 · F-27 · F-28 · F-29 · F-12 · F-13

Exit  The palette runs against live data with the mock path removed from the default build.

Phase 6

Start Android for real

Fix the Gradle DSL and scaffold a buildable app, stand up UniFFI and the cdylib so a native library exists, and settle the IME/ShareTarget capture design before writing feature code.

F-33 · F-34 · F-35 · F-32

Exit  A debug APK installs and completes one round trip with a Linux peer.

What's solid

Worth stating plainly, because the list above is long and the foundations are not the problem.

Module boundaries

The split across crypto, discovery, transport, protocol, history, and hashing is clean, and the core has no UI dependencies. The structure will hold as the gaps get filled.

The hashing module

Correct BLAKE3 throughout, with a genuinely useful incremental StreamHasher. INV-05 is honoured with no SHA-256 anywhere. Only the misnamed Merkle function needs attention.

Protocol types

Well-chosen message shapes, content-addressed by hash, with a sensible length-prefixed framing scheme. The types survive a codec swap unchanged — only the encoding is wrong.

Session detection

The X11 / wlroots / GNOME detection logic is thorough and correctly prioritizes XDG_SESSION_TYPE with a WAYLAND_DISPLAY fallback. It just isn't used to select a strategy yet.

Test hygiene

74 tests pass, and they're readable and well-named. The problem is coverage shape, not quality — they test units in isolation and never cross a real boundary.

Documentation

Doc comments are unusually complete, and the invariants in memory.html are specific enough to audit against — which is what made most of this review possible.

One process note

The commit log says "implement complete shunkan-core library", "implement desktop-linux tauri daemon", and "implement android project skeleton and uniffi ffi bindings setup". In fact the transport cannot connect, the daemon contains no Tauri and calls no core module, and there is no UniFFI anywhere in the repository.

The green test suite reinforces this: 74 passing tests, none of which crosses a module boundary in the way the product does. memory.html asks future agents to mark tasks complete once "automated tests pass" — that gate is currently satisfied by tests that would pass even if the transport were deleted.

Worth tightening the definition of done to something the tests can't fake: an integration test that stands up two real endpoints through the public API and syncs a clipboard item end to end. That single test would have caught F-01, F-02, F-08, F-10, and F-16.
